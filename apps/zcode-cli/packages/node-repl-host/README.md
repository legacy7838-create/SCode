# @zcode/node-repl-host

The shared host for `node_repl`: the JS execution surface (with only the `js` tool) and the two domain
bridges (Browser Use, Computer Use) are both here.

## Why It Is a Separate Package

The host is **shared across official capabilities** and does not belong to any single plugin. It used to live inside `browser-use-plugin`, which had the following consequences:

- Changing Computer Use required modifying the browser-use package;
- The CUA SDK and documentation each had a manually maintained copy inside browser-use;
- `resolveBuiltInNodeReplMcpServers` only looked for host artifacts under browser-use's rootPath,
  so once the browser-use package was missing, even CUA's own enablement could not obtain the host.

The registration side was already consolidated in the CLI core (`bootstrap/src/app/built-in-node-repl.ts`, with the criterion
"either bua or cua enabled"); what was always missing was **artifact ownership**. This package puts the source code in its proper place.

## Artifacts Are Still Carried by Plugin Packages

`dist/mcp/server.js` and `scripts/computer-use-client.mjs` are in the SEA release manifest
(`OFFICIAL_BROWSER_USE_REQUIRED_SEED_PATHS`); their paths cannot be moved. So browser-use's build packages from this
package's `src/server.ts`, and CUA's client/docs copies are generated by the build script rather than manually maintained.
Moving artifacts out of the plugin root directory would require changing both the SEA manifest and bootstrap's hostPackage resolution; that is a separate step.
